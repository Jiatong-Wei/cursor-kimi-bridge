### 1. 噪声带判读

**结论：成立（若统计量是 best）；「等价」不成立；5 集对 best 没有统计效力。**

「不可声称超越」我同意：best 差 6mm（0.088 vs 0.094），且来自不同回合。OBS-35 把 ±0.05 写成 5 集决策带，这是预注册启发式，不是置信区间。n=5 的 Wilcoxon 符号秩检验两-sided 最小 p=0.0625，**原则上到不了 0.05**。所以「不可称超越」成立，「噪声带内不可分辨 / 已追平」过满。

更严重的是：你们用 best 当主统计量，等于让每个策略报名自己最顺的那一个点。π₃ 赢在 ep0，SmolVLA 赢在 ep1。median/mean 下 SmolVLA 反而更稳（全落在 0.088–0.156；π₃ 被两局 IK/不接近拉到 mean 0.281）。这不能反过来说 SmolVLA 赢了——π₃ 的 mean 被协议失败污染——但足以说明 **best 对比在方法上就是错的**。

### 2. 配对方法漏洞

**结论：#10 死角不污染这张 5 集表；固定表仍有你们没写出来的缺陷。**

#10=(0.358, −0.188) 是回合序号 10。5 集策略只跑 ep0–4，oracle 兜底是 ep5–7（与 JSON 中 ep5=(0.595, −0.249) 一致）。这张三代表的 min_ee **没有经过死角**。它污染的是 10 集批次的 oracle 成功率（r7 ep10），不要和策略 best 混谈。

没看到的缺陷：

1. **配对做了，统计没用。** 同 xy 是配对设计的前提，主表却报 unpaired extrema。
2. **5/13 点位，还是表头最「好打」的一段。** 有意避开 #10；不能外推工作空间。
3. **n=5 是 5 个点位，不是 5 次独立重复。** seed=0 锁死，点位内物理噪声几乎看不见。没有种子轮换就没有空间泛化误差。
4. **ACT-dws 协议不同构。** 同出生点，但 180 步 vs 390、无 oracle、报告写的是 `state_cube_pose` 不是 `--state_cube_live`、2/5 IK 早停。SERIES 写「同 13 点位、4.5、clip 0.01」对 dws 行过满。
5. **π₃ 与 π₄ 捏成一行。** 0.094 是 π₃ ep0；0.101–0.113 是 π₄ 的 5+10 集。这不是一个策略的一个分布。

### 3. 结论过度声称 / 对比公平性

**结论：不成立。** 「约束在数据不在架构」超出证据；对比也不公平。

证据只支撑：**在这份 DAgger-r4 数据、这个评估器、双方 0/5 抓取的前提下，接近距离没有拉开到可以谈架构胜利。** 推不到「瓶颈是数据所以换架构无效」。双方都没过 ~0.05 抓取线（OBS-36 已写「最后 5cm 不在配方半径内」），0/5 vs 0/5 不能鉴定约束在哪。

不公平处：

- SmolVLA 吃的是 **ACT 四轮 DAgger 聚合 28197 帧**，不是「零任务工程」的数据。零的是今晚没再写采集器，不是数据侧零工程。
- 12k×batch2×0.85 epoch vs 专用管线四轮+门禁+π₃/π₄ 选型，不是同预算对照。
- 参数量 450M vs ~45M，但见下条新发现：预训练视觉很可能根本没加载。
- 「失败模式完全不同、交互更激进」只对 **位移** 成立（1.518m 击飞）。**举起** 的项目纪录仍是 dws ep3 的 cube_z=0.129 + grasped=True；SmolVLA 最高 z=0.116，没过 0.12 线。击飞 ≠ 更接近成功。

可保留的弱表述：同数据同评估器下，这个 VLA 动作头一晚能进入专用 ACT 的接近带。不要写成架构无关 / 数据决定论。

### 4. 缺陷清单完整性

**结论：§6 五条都对，但漏了更致命的几条。** 已写的 batch2 / 无语言 / 0.85 epoch / transformers 跨版本 / 0/5 不要当突破——同意。遗漏：

- **评估 `n_action_steps=10` vs 训练 chunk/`n_action_steps=50`。** 对 ACT 同期评估也是 10，三代之间还算同构；对 SmolVLA 论文用法是错配。12k 的 0.088 可能部分是短视界伪影。
- **相机键 `observation.images.wrist`，实机是世界系固定机位 224²**（VERIFY v6.1）。再 `resize_imgs_with_padding: [512,512]`。预训练 VLM 的腕部/多视几何对不上（即便权重加载了也不对；没加载则更无所谓，但表上仍写 450M VLA）。
- **特权状态。** 12 维含 cube xyz，评估 `--state_cube_live`。两边都能看活方块位置；不是纯视觉策略对照。
- **catastrophic forgetting 在本配置下不适用**——VLM 没被微调，因为没加载也没解冻。真正的坑是相反的：预训练没进训练图。
- **flow-matching 动作头 + clip 0.01**：激进击飞更像动作分布+裁剪，不像语言条件探索。
- 报告 JSON 里 SmolVLA 的 `"policy_type": "act"` 是生成器写死，别让后人当事实。

## Grok

**三轮复核完成。** 五份 JSON 的 median/mean/best 与 SERIES 表一致；`v3eval-chain.sh` 证实每组都是新起 server 并传入不同 `--task`（空组是 `""` 不是缺省 `"pick up the cube"`）；n10、clip 0.01、同一出生点表 ep0 起。协议方向对。下面四问；机制叙事需要改口。

独立配对（只比五组都有的 **ep0–2**；std 的 ep3/ep4 扰动组没跑）：

| ep | 出生点 (x,y) vs 标准指令「left + mid」 | std | para | wrongside | irrelevant | empty |

### ① 排序是否合理

**结论：median 排序可以当现象记下；不能当「语义理解」的证据。同义改写最差、空指令不是最差，与「套模板的词面匹配」相容，与「读懂方位」不相容。**

训练模板（`make_lang_dataset.py`）是 `pick/grasp/grab the red cube` + `left/right/ahead` + `close/mid/far` + `place it at the target spot`。标准指令几乎是模板原句；同义改写换成 block/drop/medium distance，训练里没有这些词，伤在词面 OOD 是说得通的。空指令走 `task=""`，动作头看不到训练过的 token 序列，退回无条件动作先验——接近距离介于「套中模板」和「换词」之间，并不反常。

但 **空间内容没有被跟随**。按你们自己的 SIDES/DEPTHS：ep0 匹配标准指令，却是 std 最差的一局（0.356，和 para 同级）；ep2 对标准指令是 right+far（应匹配 wrongside），std 却在这里拿到 **best 0.042**，wrongside 反而最差（0.226）。若模型在用 left/right，符号应反过来。当前排序只支持「像训练句就好些」，不支持「听懂方位」。

「2–4 倍」来自 **median 0.068 vs 0.132–0.286**。改用公平的 n=3 mean：std 0.155 vs empty 0.177 vs wrongside 0.176（约 1.1×），只有 para/irrelevant 明显差。**显著**二字没有检验：n=3 配对 Wilcoxon 两-sided 最小 p=0.25。SERIES 里 mean 已经写了，thread 只报 median 会偏袒 std。

### ② v3 无 v2 同权对照

**结论：这是混杂，而且你们已经部分写进限制了；「v2 三次抓取未复现」不要再往语言分支上归因。**

v3 是独立 36k，不是 v2 resume，权重、数据（多了 26 条任务串）、优化轨迹都不同。v2 的 grasped=True 三次还把 n10 一局和 n50 两局加在一起，再和 v3-n10 比抓取数——口径不一致。语言扰动的干净结论只能来自 **v3 内部换指令**；跨 v2/v3 只能说「另一条训练跑出来的行为不一样」。

缺的对照是：同一套 5 句指令打在 **v2-36k**（没在 26 模板上训过）上。若 v2 几乎不敏感、v3 敏感，才能把敏感性归因到语言分支训练；若 v2 同样跳，那是评估期 task 字符串的扰动，不是「学会了语言」。

### ③ 3 集 vs 5 集

**结论：不对称成立，而且是可选停止风险。** 链脚本里写死了 std×5、其余×3（`v3eval-chain.sh`）。ep0–2 配对仍有效；std 的 median 碰巧用前 3 集也是 0.068，所以 **这个具体数字没被多出来的两集救**。但这不让 5 vs 3 变成合法设计：扰动组没机会打 ep4（std 0.053 那种接触局）。主表应只报共有的 3 集，或补跑扰动组到 5。

### ④ 下一步优先级

1. **先补协议，不烧 60k。** 扰动组补到 5 集（同 ep3/ep4），主表只用配对。便宜，去掉你自己写下的限制。
2. **v2-36k × 同一 5 句（各 5 集）负对照。** 这是「语言训练是否造成敏感性」的鉴定实验，比再加步数信息密度高。不抢现在的卡也可以排在空档。
3. **空间跟随**：不要再用同一句打全部出生点。按 `SIDES(cy)/DEPTHS(cx)` 给 **当句正确** vs **当句取反** 各跑一遍同一出生点。现在这套设计测不了跟随。
4. **60k 加练排最后。** v2 已经演示过加步数 → 接触更猛、仍 0/5 放置。v3 同样 0 抓取。没有新数据配方时，60k 多半再买一次更猛的击飞。
5. **写作可以冻方法、不要冻「显著理解语言」。** 可声称上限：*在随机初始化且冻结的 VLM（含文本）+ 特权状态 + 模板任务串训练下，评估时换成训练分布外的词面，闭环 min_ee 会变差；空间语义跟随未被支持；统计效力不足。*

### 机制：「cross-attention 在没用视觉时仍用语言」

**不成立，至少没被本实验证明。** v3 训练日志仍是 `load_vlm_weights=false` + `freeze_vision_encoder=true` + `train_expert_only=true`：视觉和文本塔都是 **随机初始化后冻结**。动作专家可以学会把「这串 token 的随机哈希」当条件——这解释了模板匹配 / 同义 OOD / 空串居中，也解释了 **left/right 跟反**。这不是 SmolVLM 的语言能力，更不是「没有视觉也能看懂话」。把这句话从 SERIES 结论②拿掉。
